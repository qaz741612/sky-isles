# G V5.1 自主美術與可玩性審查

對照基準是 PR18 原 V5 `8849b89` 的真實工程，並實際檢視已認可 C V3 的 Blender 主視圖。沒有以附圖或 AI 圖冒充實作。C V3 作為構件厚度、木鋼玻璃材料區分、主體與廣場尺度的比較，不把兩島面數或測試案例數當成美術評分。

## 第一輪：水流層次與景觀組織

[第一輪原圖與紀錄](iteration-1/SELF-REVIEW.md)保留實際模型。檢視主視、正面、背面及水工近景後，發現白沫規律過密、水色接近、廣場缺少用途、原始大倒角成本過高。

修正：分成上游、跌流、下游與消能段；以不透明曲面、水色帶、少量不規則白沫幾何表現流向。降低重複白條和不必要倒角。景觀先依迎賓、前庭、觀閘、S22岸線四區配置，保留中間活動淨空，沒有隨機撒盆栽填滿地面。

## 第二輪：真正的水工剖面、四面建築與接地

[第二輪圖像及紀錄](iteration-2/SELF-REVIEW.md)指出渠道內壁和消能塊遮住水流、材料對比仍弱。補充塔頂、入口雨棚、側背面窗框與木金屬遮陽層，保持原建築量體和可走門廊，不新增假樓梯或室內暗示。

後續再從實際匯出 GLB 切剖面，而非只看好看的主視圖：原寬基礎頂面接近水面，壓縮下游斷面。基礎下沉，窄墩身承接原橋墩並有實際搭接；內壁頂面隨水流下降、消能塊低置，三條通水剖面恢復清楚的連續下降。對應[實際三角面量測](hydraulic-geometry-comparison.json)。

第3～5次檢視發現水位牌未落地、座椅靠背沒有支承及舊水下支承被誤列為可落地面，均先修正：展示牌加真實立柱和基座、四張原位座椅補八根金屬背柱，移除16個非公共水下支承三角面。原 V5 的公共乾地三角資料保持相同。這些是明確問題的修正，沒有整座重建。

## 第六輪：原生手機視角不能只驗證相機距離

[未通過畫面與紀錄](iteration-6/SELF-REVIEW.md)：模型已固定，但指揮中心入口的手機原生旋轉畫面，角色下半身被前景附屋屋簷遮住。舊頭部／軀幹中心探針沒抓到，不能標為通過。

只修改 G 專用 `floodCameraConstraint`，補成頭、軀幹、身體兩側、低位兩側六條視線，維持有效避障偏移直到原方向連續安全，避免靜止時反覆退回屋簷。沒有改共用相機、玩家參數、F/A/C、GLB、門廊或建築外型。單元驗證320個站位／方向／桌手機組合的六探針與靜止穩定；瀏覽器另外驗證原生入口六探針及全景往返後相機、orbit恢復。

[同模型、同站位及操作參數的手機修正對照](comparison-camera.png)另外列出；不能和 Blender 外觀改造混淆。原生 orbit、距離與FOV沒有拉遠，G 避障後的實際相機位置會改變，報告不冒稱所有原生前後圖的最終相機完全相同。固定 QA 和 Blender 的前後對照才逐欄核對相機位置、尺寸、旋轉／取景比例一致。

## 最後逐項檢視與實際限制

- 遠景：三孔閘體仍是水工主體，指揮塔是另一明確地標。沒有增添第四主建築或新塔壓過原配置。
- 近景：可見閘板、導軌、螺桿、檢修平台、混凝土壁厚、流線與水位差。白沫和水色是靜態示意，不宣稱流體工程模擬。
- 四面與俯視：重新檢視最終正背左右、屋頂、S22跨水段、下游和塔頂圖；保留完整側背窗框、基座、木構和屋面收邊。
- 景觀：原11處樹幹與4處座椅位置保留，以樹冠及成組線性植栽形成遮蔭／邊界；水位牌有接地，廣場留白仍供通行和停留。不是把全部空地種滿。
- 原生玩家：桌機、手機直橫式及水岸、入口分別截圖。狹長手機不可能同時看見全島所有設施，需正常旋轉；不拿QA遠鏡頭當預設玩家畫面。
- 遊戲資料及碰撞：最終工程結果見[報告](REPORT.md)和[test-summary](test-summary.json)。工程通過不等同使用者已認可藝術品質。

**仍待人工驗收**：是否達到使用者對C V3以上的主觀精緻度要求、苑字與水利園區遠景辨識、真機長時間觸控舒適度、硬體FPS／發熱及所有自由鏡頭組合。Cycles64樣本圖有少量採樣顆粒；遊戲則採原世界照明，兩者不能互當硬體效能證據。沒有隱藏這些限制，也沒有宣稱人工美術驗收已通過。
