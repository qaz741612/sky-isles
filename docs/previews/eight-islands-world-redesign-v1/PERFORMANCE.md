# 全世界效能比較

八島同時載入、1440×1000、相同預設探索站位。Chromium 154 / SwiftShader 軟體 WebGL，2 vCPU 配額、8 GiB 記憶體；不是實際手機 FPS 測試。

| 視角 | Draw Calls：V4 → 本輪 | 三角形：V4 → 本輪 | 紋理數：V4 → 本輪 | 控制器 CPU ms：V4 → 本輪 |
|---|---:|---:|---:|---:|
| 交通島一般探索 | 137 → 159 | 45,294 → 36,139 | 15 → 16 | 0.382 → 0.121 |
| 青年島較高負載探索 | 174 → 204 | 58,148 → 47,314 | 15 → 16 | 0.139 → 0.108 |
| 完整八島全景 | 301 → 345 | 99,066 → 79,006 | 15 → 16 | 全景暫停人物輸入 |

全景 Draw Calls 增加約 14.6%，三角形下降約 20.3%。新增島內鋪面、各島材質批次及接地陰影增加 draw calls；細化橋欄、減少不必要欄柱與低面數植栽降低三角形。額外紋理是一張各島共用、程式生成的 64×64 RGBA 柔邊影（16 KiB 原始像素），無大型外部貼圖。

CPU 為相同站位靜止時真實 Player 更新，7 組 ×100 ticks 的每 tick 中位數，包含原人物動畫、地面／護欄／相機查詢，不是整幀時間或 GPU 時間。V4 固定編譯檔由 Vite 靜態根目錄提供，含開發 client 注入；本輪使用 Vite preview。開發 client 不在量測的 Player 函式迴圈與 WebGL draw counts 內，原始資料保留服務方式與兩份編譯檔 SHA256。

維持按島合批及剔除，沒有合成一個不可剔除的全世界建築網格。相機使用附近靜態牆／屋頂空間索引，測試中的最大候選數記錄於逐裝置空間稽核 JSON。動態更新維持列車、原角色、風鈴、雲海與蘑菇；沒有每島增加光源或每幀重建靜態建築。

取捨：材質／遮蔭與場所層次提高了提交次數；本次樣本的三角形與控制器成本下降。不能從這組數據推論任何真機穩定 FPS、耗電或發熱，仍待人工實機長時間驗收。
