## 集中維護與碰撞策略

1. 編輯 `src/data/yuan-plan.json` 的八島與中繼節點、Bezier 控制點及寬度，再執行 `npm run generate:yuan`。`compressionXZ` 記錄本輪已套用的壓縮比例，不會再次乘算座標；布局應編輯節點與控制點。`src/data/yuan-layout.json` 與 `yuan-surface.json` 是需一併提交的可重現生成物。
2. 生成器將中心線展寬、加入端點圓帽與交會平台，再做 Boolean union。島面輪廓與原有 28 邊柱體一致，路面扣除島面部分，避免疊面閃爍。
3. 從整個共享可行走區域的外輪廓與洞邊界建立護欄；島嶼圓周保留原有懸崖，不另加環島護欄。交會點內部不生成護欄。
4. 可見護欄與水平碰撞使用同一批 boundary segments，碰撞以空間格網查詢附近護欄，並採細分位移防止高速穿越。
5. 全路面採共同水平基準，實際 Float32 三角面坡度為 0%，低於 10% 上限；目前生成器會拒絕不同高度的節點，不會默默產生未驗證坡道。
6. 島面精確三角邊緣可能漏掉中心射線；角色加入腳底範圍內 0.03 單位的備援探測，只在中心射線無命中時使用。
7. 交通島西側既有道路橋連同護欄、支柱及碰撞面向 +Z 平移 1 單位，讓新中央橫向入口通行；車站、鐵道、列車與其他七島建築維持既有模型。
8. Boolean union 採 MIT 的 polygon-clipping 0.15.7，僅於 Node 生成階段使用；三角化使用既有 Three.js ShapeUtils/Earcut。瀏覽器不載入 Boolean 套件，授權與間接依賴聲明已保留。

## 限制

圖上的 21 節點與 22 邊均連通，生成的共享區域也只有一個連通分量。自動化會用真實控制器、路面與交通島碰撞面走過全部邊、雙向入口及交會轉向；不以圖論連通取代實際步行測試。島嶼本身的懸崖仍能走落，會回到最近安全檢查點。未新增另外七島的主題建築。
