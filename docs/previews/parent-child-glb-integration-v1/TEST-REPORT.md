## 瀏覽器結果與早期失敗

使用正式建置 `PLAYWRIGHT_BASE_URL=http://127.0.0.1:4187`，Chromium／SwiftShader。功能稽核設定 `BROWSER_QA_SCALE=1`，桌面 960×640、手機 CSS 430×739、DPR=1。**完整 DPR 遊戲截圖與 FPS 測量另外執行，不以低解析度功能測試證明效能。**

初次 14 個裝置案例中 7 通過、2 為裝置限定跳過、5 因 120／240／300 秒期限失敗。桌面親子島已完成全部斷言但在 GPU 清理逾時；其餘手機卡在 DOM 點擊／版面查詢等待，並未走到路線斷言。

後續把純 DOM／工程時間步進檢查的重複 GPU 光柵化停下，保持真正模型、UI、Player、raycast、rAF 相機與碰撞邏輯；延長軟體 GPU 初次載入預算並釋放 WebGL context。**沒有為通過斷言更換模型、移除碰撞或修改人物速度。**真正影片、預覽及 FPS 全程正常繪製。

- 最終手機重跑：**5 通過、0 失敗**，[紀錄](logs/browser-mobile-final.txt)。
- 最終桌面親子島重跑：**1 通過、0 失敗**，[紀錄](logs/browser-desktop-final.txt)。
- 配合初輪已通過且執行程式未變的案例，共 **12 個不同案例通過、2 個裝置限定跳過**。這是分批結果彙整，不聲稱一次完整指令全部綠燈。
- [初次超時紀錄](logs/browser-initial-timeouts.txt) 保留供檢查；[機器可讀彙整](test-summary.json)。
- 沒有重跑整個倉庫所有歷史截圖工具及每個既有 e2e 檔案；本輪選擇親子館、現有車站頭頂、22 路線、全景、手機版面與輸入回歸。音效／解謎來源雜湊未變，既有單元測試通過，沒有將音效聽感宣稱為實機驗收。

## 真實畫面與錄影

`desktop-explore.png`、手機橫直式為原玩家跟隨相機；拍照前定位到指定前庭站位。`island-45.png`／`island-top.png` 明確為 QA 相機，政策 HTML 標籤隱藏，未移除遊戲模型。

原生步行影片錄影前定位到 S05 南入口，之後只用原生鍵盤／滑鼠走到親子館門廊。沒有直接改玩家位置、固定步進、加速或後製補幀。錄影每 15 個 compositor 影格擷取一張，保留原始時間戳；影片容器幀率不是遊戲 FPS。首輪逐張擷取產生過多重複影格，該次中止資料只保留於 work，不混入交付影片。原始擷取 712 張、237.033 秒；H.264 使用 40ms 時間格，最大時間戳捨入誤差小於 20ms，最後另留 1 秒靜止尾幀。詳見 `operation-log.json` 與 `video-validation.json`。它只示範此入口至門廊，不冒稱真人走遍全部四入口或整個八島。
