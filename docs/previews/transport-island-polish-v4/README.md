# 交通島 V4｜藺編遮陽車站與開放廣場

基礎為 V3 `70091a429bdbecafa053c3b8964dd34863ba5641`，新分支 `codex/transport-island-polish-v4`。僅重製交通島內部，八島 B 配置／半徑／Bezier／22 路段與 4.8 路寬保持不變；沒有合併或正式發布。

## 設計判斷

V3 的站體、格柵、壁畫、招牌集中同一正面，列車藏在背後，廣場則是孤立矩形加散放設施。V4 以空間關係重新整理：

- 站體收向西北，減少封閉深度、保留屋頂投影，以單一不對稱折線屋頂及較深的入口框架建立主輪廓；不是放大整座建築。
- 北側短軌道向東移，讓列車在預設桌面與手機視角、完整往返過程中均能露出。保留展示鐵道的安全隔離，沒有搭乘功能。
- 五音文化牆移至東側停留帶，圖案放大 40%，不再掛在入口前；願景台移到西側抵達帶，避免擋住圖案。
- 石色廣場串起各入口、車站、閱讀與月台接近區；木色地帶引導到凹入口。東側僅保留一座面向鐵道的座椅，植栽收在少量島緣段。
- 藺編表現改為轉角兩面的粗編帶遮陽屏風，構件有交錯前後與厚度；不編造工藝歷史，也不靠站名宣稱文化品質。
- 四周以矮牆、木色收邊、單道細金屬扶欄取代密集層疊；軌道隔離也減少水平層數與柱密度，保留真實碰撞。
- 微縮道路橋移除，四個使用者提供的政策願景題目完整保留。場景僅短標題及圖示，點選後沿用既有可關閉、可捲動政策視窗閱讀，不改正式政策 JSON。

V3 實際繞行紀錄還發現：站後座椅位於行走帶，跨過座面時產生短暫離地；V4 把座椅移出月台接近路徑。V4 第一輪又找到願景台遮圖案、視窗關閉後焦點及站前向北旋轉時的遮擋，均列入修正及回歸，沒有以單元測試取代看圖與操作。

## 實際操作

[實際操作短片：129.4 秒、1280×800 H.264 MP4](exploration.mp4)與[操作紀錄](operation-log.json)：由原生鍵盤／滑鼠控制真實遊戲，包含出生走到凹入口、返回、閱讀願景、移向文化區、接近月台、旋轉及全景返回。錄影過程不使用傳送或固定 dt 加速。這是自動化原生輸入的無聲錄影，不是人類手持真機錄影；瀏覽器錄影工具不收錄音軌，既有遊戲音效程式保留。

## 資料與工程

主要配置集中在 `src/data/transport.json`，取代帶版本號的舊執行資料。舊 V3 資料及擷取工具保留在基礎 Git 提交，沒有讓兩套場景並存；既有 V3 報告與圖保留。

[layout-audit.json](layout-audit.json)列出站體、入口、月台、列車掃掠、文化牆、願景台、座椅、未實作 NPC 預留及全部碰撞邊界。站體封閉主平面由 `4.4×1.8` 改為 `4.05×1.4`，約 `7.92 → 5.67`；屋頂投影控制在 `4.7×2.7`。初排站後僅 .7 單位不足通行，縮減後方實體後保留約 1.3 單位，後方屋簷也成為月台接近路徑的遮蔭；約 1.3 為碰撞邊界間距，構件表面之間約 1.15，扣除角色安全餘裕後可行走中心帶約 .48。不是靠放大提升地標感。

出生 `(0,.5,3.5)`、交通風鈴 `(4.6,0,3.6)`、蘑菇約 `(3.926,0,4.799)` 不動。文化圖案／音符色／解謎順序 `[2,4,0,3,1]` 保留；點圖案可在同一視窗放大閱讀線索，實際敲響原風鈴的玩法不變。四項願景只用使用者題目，清楚標明非核定或完工工程，沒有預算、期程或核定資訊。

交通島 23 段島緣碰撞與 V3 **逐點一致**；道路與外部橋欄未改。可見牆／扶欄／屏風／座椅有對應水平阻擋，沒有刪除碰撞來避開卡住。

最小共用修改有兩處：關閉 3D 點選開啟的視窗後將焦點還給場景；相機在交通島範圍以實際幾何射線檢查遮擋並收近，走出遮擋後由既有平滑跟隨恢復。使用者設定的 orbit／zoom 不變，其他七島不啟用此限制；角色速度、造型及基本物理不改。沒有把相機拉遠來掩蓋配置問題。

## 尚待人工驗收與限制

- 文化意象、建築是否夠有地標感、各預設鏡頭的視覺主次需使用者實際判斷，自動化不能證明美術品質。
- 外部步道紫色護欄仍可能形成較重背景；依限制沒有重做它們。交通島僅整理交接及島內防護。
- 相機在靠近屋簷／牆時會收近，極端近距離、凹入口內與快速連續旋轉的手感仍需人工測試；沒有完整室內或全世界相機避障系統。
- 真機 iOS Safari、Android 的長時間流暢度、溫度、記憶體、手指遮擋及音效實際聽感仍待驗。沒有把錄影或 Chromium 裝置模擬當成真機驗收。
- 無 NPC、乘車、任務或新音樂；舊 NPC 未實作預留點因文化區動線調整移到東側，位置與理由留在資料，沒有建立角色。
- 防護保障一般步行；刻意跳躍／蘑菇／滑翔仍可能越界，保留最近安全檢查點復位。

完成後只提交獨立 PR，等待驗收；不合併、不更新 Production、不延伸其他七島。

## 重現方式

```sh
npm ci
npm run build
npm run lint
npm test
npx vite preview --host 127.0.0.1 --port 4185 --strictPort
```

另開終端：

```sh
npx playwright test --workers=1 --retries=0 --timeout=240000
node scripts/capture-transport-v4.mjs http://127.0.0.1:4185 after
node scripts/audit-transport-v4.mjs
node scripts/record-transport-v4.mjs http://127.0.0.1:4185
```

錄影需 Playwright 的 FFmpeg 執行檔。本環境未下載新依賴，使用已安裝的 `/usr/bin/ffmpeg`，在 `work/playwright-video/ffmpeg-1011/ffmpeg-linux` 建立工作區別名，僅對錄影命令設定 `PLAYWRIGHT_BROWSERS_PATH`。一般開發環境亦可用標準 `npx playwright install ffmpeg` 安裝測試工具。原始 WebM 以 FFmpeg H.264／yuv420p／faststart 轉成 MP4，不改播放速度、不加入音樂。

V3 基準圖來自獨立建置的 `70091a4`，不是用 V4 假造。圖檔尺寸與 SHA256 見 `images-manifest.json`；它用來核對本次 GitHub 上傳，不是宣稱不同 GPU／字型環境會產生相同位元組的截圖。
