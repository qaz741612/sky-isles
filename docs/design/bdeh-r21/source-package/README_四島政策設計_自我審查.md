# 苑裡政策島｜B / D / E / H 政策主題 3D 設計研究

## 檔案性質與狀態

本包是使用者要求重新設計後，在本機**實際重新產生的四座 GLB 與完整同源六視圖**，不是 AI 插圖或僅有文字的建築概念。所有幾何以 `build_r21.py` 產生，`make_boards.py` 僅將同一套模型影像排成設計圖板。

**離線幾何預檢完成；尚未進入 Three.js 遊戲或真實手機操作驗收，也沒有 Blender .blend。** 目前不宣稱四座正式已超越 C 島 V3 的美術要求；不核准合併或部署。使用者無須把程式研究成果視為正式設計驗收。

## 真正的空間、路網與尺寸驗證

- 重新由 `road-candidate-r2.json` 的 **22 段候選 Bezier** 產生島內 4.8 單位寬通道；T4 採 `(51,-47)`，S06 右上往左下斜接 E 島，未修改已認可 F/A/C/G 的世界座標。
- B 的既有四個對外橋口 S08/S12/S13/S14 不移動，但本次離線提案將**島內通路重新接成北側、東側的串接動線**，保留完整環抱建築可用區。這是候選方案，需要在正式世界中重新生成並驗證，不能拿本模型取代原 PR 中路網。
- B、D、E、H 的指定尺寸只以實際 GLB 外框量測，不以原設計標籤自稱尺寸。具體數值與結果見 `qa/geometry_audit.json`、`qa/assets.json`。
- 4 島候選 4.8 步道的離線平面連通區均為 **1**；建築構件的島緣越界、低位占用 4.8 核心、懸挑屋面過低警告皆為 **0**。
- 各島保留單一 3×3 NPC 預留用地幾何研究點，但**未製作 NPC 角色或對話系統**。
- 高架綠脈與連橋視為非公共建築構件；**沒有宣稱玩家可攀登或在上面行走**。

## 自我挑刺與修改紀錄（重點）

1. **第一輪，退件：** B 兩道弧形翼與岩面越界；D 屋翼壓出岸線；E 架高綠廊像浮空結構。對主體尺寸、位置與跨路門廊方向重設。
2. **第二輪，重算：** D 改成跨街連接兩座服務量體的承重拱，屋面不再停在兩棟樓之間；E 綠廊兩端真正接在建築，跨步道處提高到安全淨空；H 保留有完整樓層的展頁學習館。
3. **第三輪，重設道路：** 原 B 四段中心放射線會切碎建築基地，改作保留橋口的北、東通行接線；重新檢查 4.8 單位通道，主體不再與其重疊。
4. **第四輪，修正島體：** 原參考島生成器的外緣會超出宣告半徑，本輪改成硬性受控的完整漂浮岩塊；整個 GLB 尺寸沒有超上限。
5. **第五輪，主題精修：** 提高照護院的兩道實體廊翼層次，智慧公所加入實際公共服務窗格與透明材質，宜居環境把一座方盒改成開放木構教學棚，教育學習館加深閱讀中庭與實體書架／論壇。

工程檢查通過不等於美術已通過。尤其正式發佈前，仍需針對遊戲視野與最終材質精修進行視覺驗收。

## 重建步驟

本包包含 `base/build_r20.py`、`base/BDEH_R18/source/*.py`、`base/BDEH_R18/data/road-candidate-r2.json`、`build_r21.py` 與 `make_boards.py`。

執行：

```bash
python build_r21.py
python make_boards.py
```

需要 numpy、trimesh、shapely、scipy、vtk、matplotlib、Pillow。本包不含第三方套件，也不含資料以外的外部依賴。生成的 `.glb`、`renders` 與 `qa` 直接位於同一個資料夾。
