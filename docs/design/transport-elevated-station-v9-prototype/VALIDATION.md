# 幾何、相機、GLB 與效能檢查

## 實際已執行

- 最終 BLEND 重新開啟檢查：9,004 個原始網格、540,704 個 evaluated 三角面，非封閉／非正體積問題0；低位實體與兩處3×3NPC區交疊0。見 source-audit.json。
- 8個車輪最低點與2條軌頂的最大高度差 **0.000500** 世界單位。
- 全尺寸東西4.8通道與地面殼交疊0，四個橋口／入口／NPC／休息與觀察位置共 **15** 個採樣點在同一個保守地面連通元件。使用0.12網格、0.33玩家半徑、四鄰接，避免斜角偷穿；樓梯僅檢查公共接近點，沒有把2D結果冒稱可上樓。所有其他路段及安心生養地界交疊0。
- 精修及候選 GLB：Khronos glTF Validator 都為 **0 errors／0 warnings**；UV、法線、PBR、1張內嵌原創256px木紋完整，沒有外部貼圖依賴。實際glTF編碼會移除少量退化面，因此以gltf-summary的實際檔案三角面為準，與匯出前source計數略有差異。
- Chromium實際GLTFLoader解碼、材質及貼圖載入、WebGL繪圖與下載SHA核對；軟體渲染測量如下。`qa/`畫面是隔離資產檢視器，不是正式遊戲。

環境是受限CPU、Chromium軟體WebGL；每次只載入一個資產，沒有其他七島、角色、物理或遊戲UI。載入時間來自localhost，不代表4G或真實網站網路速度。量測在Blender渲染結束後執行，避免兩工作互搶CPU；不外推iOS、Android或桌機GPU真實FPS。展示版透射玻璃會增加額外pass，因此提交面數高於檔案三角面；候選改透明薄玻璃取消折射pass，未把這種近似回寫精修來源。

候選仍約18MB、90網格批次，不能直接宣稱適合所有手機。後續可在取得外觀驗收後評估meshopt／量化、依距離LOD及玻璃pass；本輪不為降低數字而更改已建立的主輪廓。

## 高度／垂直動線調整

平台步行面維持3.75；前側平台橋底維持3.289，鐵軌處改成真正凹槽斷面，其局部底部約3.02。列車整體向下平移0.38，沒有縮小，車體最高約5.888，與V9約6.208有明確差異；這是修正原代理的輪軌／月台關係。門框高約1.62，車門與內部地板對應；月台至車內仍約0.17–0.23高差，列車為不可搭乘靜態展示。

左側雙跑樓梯每級約0.153、踏深0.273、寬1.0，上層連橋寬1.1，右電梯連橋寬約1.23。幾何相連不能代替原遊戲步階控制：仍需獨立踏階／坡道碰撞及膠囊頭頂驗證。電梯未做升降功能。

## 鏡頭

- 桌機：dist16、pitch0.60、yaw0.16、垂直FOV55、原出生點加1.5目標偏移；完整站房、高架、列車均在畫面內。
- 手機預設：dist22、pitch0.67、yaw0.12、垂直FOV58；有部分棚架、列車及垂直動線被裁切，**不宣稱通過完整車站構圖**。
- 額外zoom28與橋口站位模擬清楚分開標示；不修改正式相機profile。玩家可否在真實手機舒適操作、相機有無遮擋，仍須正式整合後測試。

## 既有遊戲與人工驗收

`npm run check` 成功：50項既有單元測試、lint、Vite build；[實際紀錄](existing-game-sanity.json)及[完整log](existing-game-check.log)。這只證明未修改的舊遊戲仍可建置，不是新高架站的遊戲碰撞回歸。安心生養來源與苑字JSON以原提交雜湊核對完全一致。
